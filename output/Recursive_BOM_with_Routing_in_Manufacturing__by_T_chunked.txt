The Integrated BOM-Routing Model In SAP B1 and similar
ERP systems, two key tables underpin production planning: BOM Table (OITT + ITT1): defines
which components go into a parent item, including quantities Routing Table (OITT joined
with OWOR + WOR1): defineshowthe item is produced, with steps including work centers,
standard times, and cost centers To computetotal cost and time, I constructed an
integrated model where each semi-finished item (SFG) would: Be expanded recursively using
BOM logic For each node (item), retrieve the routing sequence (StepID,OperationCode) From
each operation, pull:-Labor Hours × Hourly Rate = Labor Cost- Machine Hours × Rate =
Machine Cost- Material Scrap RateandYield Efficiency Aggregate recursively back to the
top-level product Example Logic Flow: From this flow, we compute: M001–1 appears: 2 × 3 ×
2 = 12 units M001 operation time: 3 × 0.2 = 0.6 hrs S001 labor: 0.5 + 1.0 = 1.5 hrs → 2 ×
1.5 = 3.0 hrs for B001 Costing per routing step is multiplied at each layer and summed
upwards How I’d Rebuild It Today (Modern Stack) If I were to rebuild this system today, I
would: UseMySQL recursive CTEsto expand the BOM hierarchy Use anormalized Routing
tablewith fields:ItemCode,StepNo,Operation,LaborHours,MachineHours,LaborRate,MachineRate
Build anETL pipeline in Python:- Extract recursive BOM from MySQL- Join each component
with its routing- Compute cost/time/material metrics inpandas- Write output to aData
Warehousetable (e.g.,ProductionCost_Fact) How the ETL Logic Works Recursive Expansion with
Cost Calculation (Pseudocode): What it actually does: Lessons from Refactoring Rebuilding
this solution in Python has revealed a powerful truth:the right tools don’t just make
systems faster — they make teams stronger.
